# 诺瓦 Nova · 学生日程助理

一个面向学生的、可运行、可解释、可复现的日程助理 Demo。左侧对话栏用自然语言驱动右侧工作台，后端提供确定性调度引擎与 REST API；**同一套引擎代码**既供后端在线计算，也供前端离线兜底。

> 定位说明：本 Demo 的意图识别是关键词匹配，排程、重排与归因全部由纯函数计算，不调用大模型。相同输入必得相同输出，每个排程决策都附带一句人类可读的理由。
>
> 视觉主题：**日漫清晰线（二次元日漫 × 清晰线骨架）**——奶油纸白 + 天空蓝主色（单一活性色，衍生层由 `:root` 派生），主容器 2px 实墨线全框、圆润体系、无弥散阴影，对话为云朵气泡 + 圆月牙尾巴；网点底纹与 banner 集中线做日漫点缀，樱花粉只做用户侧标记；荧光笔底色只做「划重点」。助理人格「诺瓦」的九态形象贯穿顶栏品牌标记、favicon 与各场景提示，设定见 [`docs/IP-DESIGN.md`](docs/IP-DESIGN.md)。

## 核心能力

| 能力 | 说明 |
|---|---|
| 目标落地 | 新建目标（考研 / 考公 / 项目导学）→ 可行性判定 → `R < 0.7` 阻断并给三条校准路径 → 拆解草案可改工时、增删、拖动排序 → 确认生效 |
| 可行性评估 | 由总可用工时 `T` 与需求工时 `D` 求比值 `R`，四档判定：充裕 ≥ 1.2 / 合理 ≥ 0.9 / 偏紧 ≥ 0.7 / 阻断 |
| 自动排程 | 30 分钟粒度装箱；不可用时段、日上限、单科目连续时长、弹性位优先级四条硬约束，违反即不排入 |
| 四级重排 | L1 顺延 → L2 压缩 → L3 替代 → L4 放弃，**有序执行**，首个通过防雪崩校验的级别即停止；支持逐条否决 |
| 重排可撤销 | 重排前写快照，撤销即反向应用快照，**不重算**，保证与重排前逐条一致 |
| 中断挽救 | 连续 ≥ 3 天无记录进入挽救：缺口量化 + 压缩 / 顺延 / 降级三选一，一键生效，零惩罚回归 |
| 偏差归因 | 固定顺序：计划过载 → 执行中断 → 效率不足 → 外部干扰；先排除计划问题，再归因用户侧 |
| 执行记录 | 计时 / 暂停 / 部分完成（25–100%）/ 跳过 / 补录；全部写入幂等 op 队列 |
| 计划交互 | 本周日程块拖动改期（日上限 300 分钟校验）、手动锁定（重排不改动）、显性「重新安排」入口 |
| 周报与数据 | 达成率趋势、科目结构、归因占比、结论/依据/已执行动作三段式周报 |
| 设置与数据 | 可用时段 7×4 网格编辑与批量复制、CSV 导出、删除全部数据（7 天内可恢复） |
| 离线与移动端 | 无后端时降级到本地引擎；≤860px 单列 + 顶端导航条（对话为首页，导航在所有尺寸下都位于顶端） |

三条防雪崩断言（同时成立才采纳重排）：

1. 单次重排后未来 7 天负载增幅 ≤ 20%
2. 任何情况下不得清空弹性位
3. 连续 3 次重排未改善 → 停止并转目标校准

## 快速开始

### 方式一：只开前端（无需任何环境）

双击 `index.html`。浏览器直接以 `file://` 打开，脚本走本地引擎，**全部功能可用**，顶栏显示「离线 · 本地计算」。

### 方式二：前后端完整运行

```bash
npm start     # 启动服务，默认 http://127.0.0.1:8787
npm test      # 引擎单测 + HTTP 冒烟
```

打开 `http://127.0.0.1:8787/`。该服务同时静态托管前端，前端与 API 同源，顶栏显示「本地优先 · 已同步」。

### 环境要求

- Node.js **22+**（仅 `npm start` / `npm test` 需要；双击打开 `index.html` 不需要任何环境）
- **零第三方依赖**：只用 `node:http`、`node:fs`、`node:path`、`node:url` 等内置模块，无需 `npm install`

### 端口与绑定地址

| 环境变量 | 缺省 | 说明 |
|---|---|---|
| `PORT` | `8787` | 服务监听端口 |
| `HOST` | `0.0.0.0` | 监听地址。容器或反向代理场景保持默认；本机自用建议显式设为 `127.0.0.1` |

```bash
PORT=8080 HOST=127.0.0.1 node server/main.js
```

## 部署到腾讯云 CloudBase

线上环境已部署，前后端同源，一个地址即可访问完整功能：

**https://demo-d1gyqshti9179e9bb-1359241594.ap-shanghai.app.tcloudbase.com/**

| 项目 | 值 |
|---|---|
| 环境 ID | `demo-d1gyqshti9179e9bb`（地域 ap-shanghai） |
| 部署形态 | HTTP 云函数 `nova`（运行时常驻监听 `9000`，由 `scf_bootstrap` 拉起） |
| 运行时 | `Nodejs20.19` |
| 访问入口 | HTTP 网关默认域名，路由 `/` → `nova`（`WEB_SCF`，已开启路径透传） |
| 函数包 | `.deploy/cloudbase-functions/nova`（约 509 KB / 45 个文件，零依赖） |

### 为什么是云函数而不是云托管

本服务是无状态 HTTP：只做「请求进来 → 纯函数计算 → 响应」，没有 WebSocket / SSE 长连接、不需要常驻后台进程、不访问 VPC 内数据库、无自定义系统依赖。按 CloudBase 的选型原则，这类服务用 HTTP 云函数即可，无需初始化云托管环境，部署更快、按请求计费且可缩容到 0。

### 构建与更新

```bash
npm run build:cloudbase   # 产出 .deploy/cloudbase-functions/nova
```

构建脚本把 `index.html` / `assets/` / `shared/` / `server/` 复制到 `.deploy`，再落入口文件（`deploy/cloudbase/function/index.js`、`scf_bootstrap`）。源仓库结构不变，`npm start` 与 `file://` 双击打开都不受影响。

更新线上代码：重新执行上面的构建，再用 CloudBase 的 `manageFunctions(action="updateFunctionCode", functionName="nova")` 上传即可。

### 部署相关的三处适配

1. **`server/main.js` 新增 `CORS_MODE=off`**：云函数经 HTTP 网关暴露时，网关会按环境安全域名自行回填 `Access-Control-Allow-Origin`，函数再写一次会得到 `<origin>,*` 这种非法多值头，浏览器直接判为 CORS 失败。`scf_bootstrap` 里默认关闭；本地 `npm start` 不受影响。
2. **入口与引导脚本**：`deploy/cloudbase/function/index.js` 复用 `server/main.js` 导出的 `start()` 并绑定 `9000`；`scf_bootstrap` 使用 `/var/lang/node20/bin/node`，与 `Nodejs20.19` 运行时严格对应。
3. **鉴权环境变量**：云函数环境变量必须配置 `NOVA_AUTH_SECRET`（≥32 字节随机串）——生产环境（`NODE_ENV=production`）缺该变量时 `server/auth.js` 直接拒绝启动；网关需放行 `Authorization` 请求头并强制 HTTPS（Bearer 明文传输）。本地 `npm start` 未设密钥时自动用进程级随机密钥，无感。

### 已知的线上限制

- **默认域名中间页**：CloudBase 默认测试域名（`*.app.tcloudbase.com`）对浏览器首次导航会展示一次「风险提醒 / 确定访问」中间页，点击一次后 Cookie 有效期内不再出现。这是平台合规策略，唯一移除方式是绑定已备案的自定义域名。程序化调用（fetch / curl）不受影响。
- **数据为内存态**：`server/store/memory.js` 的数据随函数实例存活，实例回收后回到种子数据。新目标与打卡记录在本机 overlay（`zx.overlay`）跨刷新存活；改期、锁定仍只写本机 op 队列，未接服务端持久化——与本地运行时的边界一致。

## 使用指引

### 界面结构

- **顶栏**：品牌、主导航（**对话 / 今日 / 计划 / 数据 / 我的**）、同步状态与日程引擎状态。按 `/` 进入对话页。
- **对话（主页面）**：默认页签。输入自然语言或点下方快捷语句，诺瓦驱动其余工作台子页；消息历史跨页签保留。
- **形象**：助理人格「诺瓦」的 v4 形象贯穿顶栏品牌标记、favicon 与欢迎语主形象；**九态系统全部落地并接入对应场景**——等待响应显示「计算中」、计时中在任务行显示「专注」、任务完成显示「达成」、中断显示「挽救」、偏差归因与负载预警显示「提醒」、无后端时顶栏引擎状态显示「离线」、关键词未命中显示「兜底」（聆听 / 离线头像原挂对话栏头像，已随对话页头部撤除，素材保留供表情包 / 周边）。设定与版权边界见 [`docs/IP-DESIGN.md`](docs/IP-DESIGN.md)。
- **工作台子页**：今日 / 计划 / 数据 / 我的，随顶栏导航或对话指令切换；目标、阶段与 `R` 值显示在工作台头部。
- **渐进披露**：每页只保留首要信息，次要内容默认收起——数据「趋势与归因」、我的「数据与隐私 / 显示与动效」。点击标题行展开或收起，展开态写入本机（zx.folds），刷新后保持。

### 四个视图

| 视图 | 内容与可用操作 |
|---|---|
| 今日 | 任务卡、达成率、弹性位。开始后可暂停 / 继续；结束后选 25–100% 完成度与状态；未开始可跳过；区标题「补录」可事后记录 |
| 计划 | 新建目标 / 重新安排；可行性 `R` 与四档刻度、「本周日程块」（拖动改期、锁定）、未来 7 天负载 |
| 数据 | 本周概览、三段式周报与预置调整优先展示；8 周趋势、科目结构、偏差归因默认收起 |
| 我的 | 可用时段 7×4 网格（点选 / 复制到工作日 / 清空 / 恢复默认）、通知开关优先展示；数据与隐私（CSV 导出、删除与 7 天恢复）、显示与动效（底纹 / 纸纹 / 动效 / 字号）默认收起 |

### 对话指令

关键词命中即触发，无需固定句式：

| 你说 | 效果 |
|---|---|
| 新建目标 / 定目标 / 改目标 | 打开「设定你的目标」四步流程 |
| 我断了四天 / 中断 / 挽救 | 进入中断挽救，缺口量化后三选一 |
| 今天学什么 / 安排 / 任务 | 列出今日任务与剩余时长 |
| 我的计划可行吗 / R 值 / 来得及吗 | 输出可行性评估与判定档位 |
| 这周落下了 / 帮我重排 / 来不及 / 崩了 | 走四级重排，给出策略、diff 与负载变化 |
| 撤销 / 恢复 / 撤回 | 回滚上一次重排 |
| 数学多给两小时 / 加时间 | 调整单科配额并重算 |
| 生成周报 / 复盘 / 这周怎么样 | 输出周报 |
| 我有点累 / 状态不好 / 压力 | 降载：把低权重项顺延到弹性位，不计断更 |
| 开始 / 计时 / 专注 | 对当前任务启动计时 |
| 确认放弃 | 确认采纳含「放弃」项的重排（L4 经确认才生效） |

未命中任何关键词时返回兜底说明，不臆造结果。

### 已知边界

- 后端不持久化（内存态，服务重启 / 函数实例回收后回到种子数据）；新目标、打卡记录、跳过 / 补录经本机 overlay（`zx.overlay`）跨刷新存活，改期、锁定只写本机 op 队列，未接服务端持久化。
- 单人演示账户：已内置 Bearer 凭证鉴权（`server/auth.js`，401/403 与写接口 429 限流，凭证由 `POST /api/auth/session` 签发），但无注册 / 多用户体系，不适合直接作为多用户服务使用。
- 通知开关仅记录意图，不实际投递推送；CSV 导出为浏览器本地生成，不经过服务端。
- 删除全部数据会先在本机留存 7 天快照，恢复入口在「我的」。
- 种子数据（用户「林清」及全部任务、记录）均为虚构演示数据，不含任何真实个人信息。
- 页面不加载第三方脚本、字体或统计代码，无埋点、无 Cookie；业务数据仅存于本机内存与 `localStorage`。

## API

基址 `http://127.0.0.1:8787/api`，全部返回 JSON。字段级契约见 [`docs/HANDOFF.md`](docs/HANDOFF.md) 第 5 节。

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/health` | 健康检查（免鉴权） |
| POST | `/api/auth/session` | 签发 Bearer 演示凭证（免鉴权；其余接口均需凭证） |
| GET | `/api/state` | 初始全量状态 |
| POST | `/api/feasibility` | 可行性评估 |
| POST | `/api/schedule` | 排程 |
| POST | `/api/replan` | 四级重排（含快照） |
| POST | `/api/replan/confirm` | 确认采纳含「放弃」项的重排（`{ result }`，L4 经确认才生效） |
| POST | `/api/replan/undo` | 撤销重排 |
| POST | `/api/attribute` | 偏差归因 |
| POST | `/api/sessions` | 打卡上报（按 `opId` 幂等） |
| GET | `/api/sync?since=N` | 增量拉取 |
| POST | `/api/sync/ops` | 批量上行（单批 ≤ 200） |
| GET | `/api/reports/weekly` | 周报 |

错误统一返回 `{ error: { code, message } }`。
